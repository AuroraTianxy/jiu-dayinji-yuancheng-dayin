# 旧打印机远程打印

把 PDF 发给家里或店里那台旧打印机。只要有一台能正常驱动它的 Windows 电脑，这台电脑就能替它从网上领取任务。

作者 [AuroraTianxy](https://github.com/AuroraTianxy) · [接入指南（开发者与 AI）](AGENTS.md)

## 解决什么问题

打印机还好好的，插在电脑上也能用。人一离开家或店里，就只能请现场的人代打。家里或小仓库通常也不方便配置公网 IP 和路由器端口转发。

这个工具把连接方向倒过来。你在手机或另一台电脑上提交 PDF，打印点的旧电脑每 3 秒主动通过 HTTPS 检查队列，有任务就下载，并交给本机已经装好的打印机驱动。**打印机和旧电脑所在网络都无需公网 IP 或端口转发。** 打印服务需要部署在提交端和旧电脑都能访问的位置。

```text
手机或另一台电脑 ──提交 PDF──▶ 你自建的打印服务
打印点的旧 Windows 电脑 ──主动领取、回报状态──▶ 打印服务
打印点的旧 Windows 电脑 ──本地打印──▶ 已连接的打印机
```

队列能在旧电脑临时离线时保留待领任务。断网重连或回执丢失时，同一任务 ID 沿用原来的打印记录。结果不明确时，页面提示到现场核对，避免自动补打一份。

## 快速开始

1. **准备打印点。** 在旧 Windows 电脑上安装打印机驱动，先用 Windows 打一张普通测试页。选好纸张尺寸。电脑需要保持联网、唤醒，且 Windows 用户会话保持登录。安装受支持的 Node.js 22 或较新版本。
2. **启动打印服务。** 在双方能访问的服务器上安装 Node.js 22+ 并下载本仓库。将 [server.env.example](server.env.example) 复制为 `.env`，填写一个提交令牌，并给每台电脑配置一个独立的领取令牌。每个令牌用下面的命令分别生成。执行 `npm run server`。打印服务默认监听 `127.0.0.1:17890`。
3. **接上旧电脑。** 通过 HTTPS 入口访问服务。旧电脑上双击 `setup.cmd` 安装依赖和填写配置。输入步骤 2 的服务地址、打印点 ID、电脑 ID 和领取令牌，再从列表选打印机。先运行 `node agent.mjs --dry-run` 核对打印机，随后双击 `start.cmd` 保持客户端运行。
4. **提交 PDF。** 在手机或电脑打开打印服务的首页，输入提交令牌和打印点 ID，上传 PDF。页面显示任务 ID，可用它查询状态。

```sh
node -p "require('node:crypto').randomBytes(32).toString('hex')"
```

HTTPS 入口可以用反向代理转发到服务的环回地址。转发时允许约 14 MiB 的 JSON 请求体，并关闭请求体与 Authorization 头的日志。配置文件、令牌和队列都由部署者保存在私有位置。每个打印点一个领取令牌，只能领取自己打印点的任务。提交令牌负责提交和查询任务，留给负责操作的人使用。

可选用 `install-startup.ps1` 在 Windows **当前用户登录后**启动客户端。单份 PDF 最大 10 MiB。当前版本使用单进程队列，每个打印点绑定一台电脑。状态「已交给 Windows 打印队列」表示驱动已接收。实际出纸还要看现场打印机状态。

## 相关项目

- [printpapi](https://github.com/LukiPrince/printpapi) 同样由客户端主动轮询，并涵盖更多平台与打印类型。当前版本采用 Elastic License 2.0。
- [Print Agent](https://github.com/jordankzf/print-agent) 由 Windows 客户端主动建立 WebSocket 连接，面向远程热敏小票打印，采用 GPL-3.0。

本项目把首版集中在一个场景。保留现有 Windows 驱动，让有线老打印机接收异地的 PDF 任务。服务端和客户端代码使用 [MIT](LICENSE)，Windows 打印依赖的许可证见 [第三方说明](THIRD_PARTY_NOTICES.md)。

## 验证

`npm test` 在本机回环地址运行，覆盖队列、令牌隔离、断线重连和模拟 Windows 驱动。准备正式使用时，用一页虚构 PDF 在目标机型上试打。
